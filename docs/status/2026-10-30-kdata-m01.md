# K-Data M01 completion report

Implementation is complete in `feat/k-data-m01`, worktree
`.worktrees/k-data-m01`. Production and real-model acceptance remain unverified.
Nothing was deployed and no production database or account was used for testing.

## Result and architectural choices

An authenticated user can create a personal knowledge space, upload PDF/UTF-8
text, observe queued/processing/ready/failed states, download originals, request
reindexing, and delete with confirmation. Existing chat optionally retrieves
personal knowledge and streams answers with document references. References are
associated with the assistant message and available after conversation reload.

Core owns authorization, files, ingestion and retrieval. PostgreSQL real arrays
provide owner-authorized exact cosine search on the existing PostgreSQL image;
pgvector is intentionally not required. Embeddings use a separate local-only
capability, never chat-model fallback. PDFBox parsing runs in a separate bounded
JVM. Leases, fencing, atomic publication and deletion tombstones protect jobs.
Cloud knowledge is denied under the existing current-message-only disclosure
policy. Velora can use the same optional Core orchestration flag; no satellite
audio/session controls or second RAG/chat service were added.

See [ADR 0030](../adr/0030-personal-knowledge-foundation.md) and
[developer/operations documentation](../k-data.md).

## APIs

Core `/v1/knowledge`, proxied by Web `/api/knowledge`:

| Method | Path | Result |
| --- | --- | --- |
| GET / POST | `/spaces` | Actor's personal space list / idempotent creation |
| GET / POST | `/spaces/{id}/documents` | Paginated list / multipart upload |
| GET | `/documents/{id}` | Safe metadata |
| GET | `/documents/{id}/content` | Protected original attachment |
| DELETE | `/documents/{id}` | Immediate retrieval exclusion, reliable cleanup |
| POST | `/documents/{id}/reindex` | New ingestion revision |
| POST | `/search` | Bounded authorized semantic excerpts |
| GET | `/answers/{conversationId}` | Owner-scoped saved answer sources |

Existing K-AI generation accepts `knowledgeEnabled` (false by default).
`knowledge.sources` is an additive NDJSON event keyed to the assistant message.
No public vectors, storage keys or chunk-management endpoints were introduced.

## Security evidence

The automated tests cover the requested security scenarios through these checks:

| Acceptance cases | Evidence |
| --- | --- |
| 1–2 upload/read | Authenticated multipart upload, original download, READY transition and owner search against PostgreSQL |
| 3–8 isolation/admin | Foreign listing, UUID metadata, download, deletion and search denial; same checks after granting ADMIN |
| 9–10 deleted/failed | Immediate tombstone exclusion; failed embedding exposes no chunks; retry publishes complete revision |
| 11–13 malformed/path/size | Real PDF parser rejection, traversal filename rejection, strict UTF-8 and byte limit tests |
| 14–15 embeddings | Missing setup, HTTP model-not-found, public/cloud endpoint rejection, no retry/fallback transport, vector validation |
| 16 injection | Malicious document text stays outside the system prompt as JSON data; model cannot modify Core identity, tools, route or consent |
| 17 sources | Correct document/revision/chunk reference, stream message association, saved sources and foreign-source isolation |
| 18–19 AI regressions | Existing cloud-consent/router/RBAC/streaming tests plus optional knowledge streaming through the existing orchestrator |
| 20 concurrency/delete | Deletion during the embedding callback and stale publication both fail to resurrect content |
| 21 worker recovery | Competing claims, expired lease reclamation, fencing and explicit final-attempt crash failure |
| 22 index compatibility | Changed dimensions hide the old index; reindex atomically publishes only the configured dimension/revision |

Prompt tests establish data/instruction separation and Core-enforced boundaries;
they do not prove semantic obedience of every real LLM response.

## Limitations and M02

Organization ownership is reserved in the domain only. It must bind to the
canonical Spaces schema and membership rules before exposing organization data.
Exact search is bounded to 100 documents per personal space and 600 chunks per
document; large-scale pgvector indexing is future work. One active model/dimension
is supported; model changes require explicit reindexing and reindexing temporarily
hides the old revision. Scanned PDFs require OCR, deliberately outside M01.

The separate parser process bounds heap/time/pages/output but is not an OS
security sandbox. Keep PDFBox patched and protect the service account and file
root. Runtime/DNS configuration is trusted operator input. A generated answer's
text remains in conversation history after deleting its source document; deleting
the conversation uses the existing separate controls. Stopped partial answers do
not persist source references; completed answers do.

M02 should address organization authorization, pgvector scale evaluation,
operational job diagnostics, richer provenance, portable encrypted knowledge
export and a verified database-plus-file restore drill. Install/configure a local
embedding model and perform real-user RAG acceptance before operational rollout.
